# 动画质控管线：检查 → 评估 → 升级

> 目的：让 319 个动画定义（221 个探索动画 + 98 个概念模板）全部达到"精品"线，并且不再退化。

## 一、升级经验十条（本轮双摆/洛伦兹/随机游走升级沉淀）

1. **动画必须演示原理本身**。双摆的主题是"蝴蝶效应"，单摆再美也是错——对照结构（两个并排、初始差 0.001 rad）才是原理的化身。评估第一问：这个动画能不能让人"看一眼就懂为什么"？
2. **对照是最强的教学法**。实测 vs 理论（随机游走的 √t 虚线圆）、A vs B（双摆并排）、有 vs 无（瓦特冷凝器）。能做对照就别做单演示。
3. **数值必须自洽**。随机游走实测 48.4 px vs 理论 54.0 px，比值 0.886 正好等于瑞利分布系数 √π/2——物理对不对，数字会说话。写理论对照线前先算清楚系数。
4. **颜色编码物理量**。洛伦兹吸引子用颜色编码瞬时速度（蓝慢→金快），一根线同时讲两个量。
5. **预跑让首帧即有内容**。洛伦兹预跑 900 步，打开就是完整蝴蝶形，而不是看一条线慢慢长。
6. **发光与拖尾是性价比最高的美化**。`shadowBlur` + 渐隐拖尾，视觉档次立刻提升，代价极小。
7. **底部 caption 一句话点题**，顶部图例说明各元素；文字区单独清底（`fillRect` 实底）防止拖影糊字。
8. **参数驱动核心物理量**，不是只调速度。验收方法：把参数从 min 拉到 max，结果应有质变（相态改变、结构改变），不是"变快变慢"。
9. **健壮性三件套**：不抛异常（`tests/all-anims.js` 自动关口）、参数极值不崩、不依赖外部资源。
10. **AI 写完必须复读**：长中文会随机混入杂词；长代码要 `node --check`；改完 js 必须升版本号再测。

## 二、检查（自动关口，每次提交前必跑）

```bash
node tests/all-anims.js     # 或一条总管：node tests/run-all.js（引擎+注册表+动画三关口连跑）
```
- 覆盖 ExploreAnim 全部 key + ConceptAnim.GEN 全部模板 + modules/*.js 全部 App 模块（render+120 帧冒烟）；
- 每个动画跑 默认/参数下限/参数上限 三组输入 × 120 帧；
- 断言：不抛异常 + 确有输出（canvas 绘制调用或 DOM 挂载，防"跑了但什么都没画"的静默失败）；
- 新动画不入库就不准合入（管线第 4 步）；模块亦同。

技术要点：Node 环境用 Proxy 桩掉 canvas 2D 上下文并统计绘制调用；`requestAnimationFrame`/`setInterval` 接管为手动驱帧（无头浏览器 rAF 只有 ~1.5fps，测试绝不能依赖真实帧率）；真实加载 engine/*.js 与 js/utils.js、js/anim.js 提供 SCI/UI；JSXGraph 用深桩走通真实代码路径。

## 三、评估（人工/AI 目检，按抽样+重点）

每个动画问四个问题，按 D→A 评级：

| 等级 | 标准 |
|---|---|
| D | 跑不动 / 空白 / 报错 |
| C | 能动，但不演示标题承诺的原理（货不对板，如旧版双摆） |
| B | 演示原理，但观感朴素（无对照、无配色语义、无标注） |
| A | 原理可见 + 对照/配色/标注齐备 + 参数有质变 + caption 点题 |

抽样规则：每批新动画全检；存量动画每次迭代抽 10%。

## 四、升级（按评级排队）

- D 级：当日修复，阻塞发版；
- C 级：优先重做（教学逻辑错误比丑更严重）——本轮双摆即此类；
- B 级：按"经验十条"套模板升级（对照/配色/辉光/预跑/caption 五件套）；
- A 级：不动，纳入回归保护（截图存档）。

升级后必须：重新跑 `all-anims.js` + Playwright 截图目检 + 升版本号。

## 五、防退化

- `tests/all-anims.js` 是硬关口，CI 级地位，失败即禁止推送；
- 任何动画改动都要过"四问评估表"自查；
- 版本号机制（index.html 全局 v=N）保证用户拿到的永远是新代码。
